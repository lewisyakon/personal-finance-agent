# 阶段 3 统计数据契约

本文档是阶段 3 统计 API 和 Dashboard 的统一口径说明。页面只展示后端
`Stats Service` 返回的结果，不在浏览器端重新汇总权威金额。

## 金额、时间和币种

- 所有金额字段以整数最小货币单位返回。人民币的 `1250` 表示 `12.50` 元。
- 统计周期使用左闭右开区间 `[from, to)`。
- API 中 `from=YYYY-MM-DD` 表示该日 `00:00:00`；`to=YYYY-MM-DD` 为方便用户使用，
  表示包含该日整天，服务内部会转换为下一日 `00:00:00` 的排他上界。
- 带时间的 `to` 不会自动延长。例如 `to=2026-01-31T12:00:00+08:00` 的上界就是该时刻。
- 未提供任何边界时，默认统计当前月份。只提供一个边界时，另一边界按 30 天补齐。
- 默认业务时区为 `Asia/Shanghai`。数据库的 SQLite 日期列物理存储为 UTC-naive 值；
  ORM 和 API 会恢复/返回带偏移的 UTC 或配置时区时间。
- 一个统计周期纳入统计的记录必须只有一个币种。没有有效交易时返回 `CNY`；纳入统计的
  记录出现多个币种时，API 返回 `STATS_VALIDATION_ERROR`，调用方应按币种分别查询，
  不能把不同币种直接相加。

## 纳入和排除规则

| 记录 | 金额统计 | 有效交易数量 | 单独计数 |
| --- | --- | --- | --- |
| `status=success` 且方向为支出/收入 | 纳入对应方向 | 纳入 | - |
| `status=success` 且方向为转账 | 不纳入收支和净流量 | 纳入 | `transfer_count` |
| `status=refunded` 且方向为支出 | 保留原始消费，计入支出毛额 | 纳入 | - |
| `status=refunded` 且方向为收入 | 按退款回款计入收入 | 纳入 | `refund_count`、`refund_minor` |
| `failed`、`pending`、`processing`、`unknown` 等 | 排除 | 排除 | `excluded_count` |

退款口径是“现金流口径”，并兼容微信的成对导出行：微信可能同时保留一条原始消费行
（`收/支=支出`、状态为退款）和一条实际退款回款行（`收/支=收入`、状态为退款）。
原始消费行仍计入支出毛额，只有收入方向的退款回款行计入收入；
`refund_minor` 是这些退款回款行的 `income_minor` 子集。这样部分退款不会把原始消费
金额误当成回款，也不会重复冲减原始支出。预算的 `used_minor` 仍按周期内的支出毛额
计算，不自动用退款抵扣预算已用额。

`net_flow_minor = income_minor - expense_minor`。转账不是收入或支出，不影响净流量。
`transaction_count` 是所有纳入统计的成功/退款/转账记录数量，失败和待处理记录只进入
`excluded_count`。

## 分类和商户

- 分类优先级为：用户人工分类 `category` > 平台原始分类 `platform_category` > `未分类`。
- `/`、`／`、`>`、`＞`、`\`、`|`、`｜`、`::` 和 `：` 可作为一级/二级分类分隔符。
  例如 `餐饮/早餐` 的一级分类是 `餐饮`，二级分类是 `早餐`。
- 分类构成按完整的“一级/二级”键聚合，同时返回一级和二级字段。
- 商户为空时使用商品/描述，再为空显示 `未知商户`。
- 分类修改直接读取交易表当前值，因此修改分类后再次请求统计即可看到新构成，
  不需要重新导入账单。

## 趋势、排行和大额交易

- 趋势支持 `day`、`week`、`month`、`year`。周从周一 `00:00` 开始。
- 趋势桶按业务时区切分，返回的首尾桶会裁剪到请求周期。
- 商户排行按指定方向的金额降序，金额相同时按商户名称排序。
- 大额交易默认 `direction=expense`，阈值是整数最小货币单位，金额大于等于阈值的记录
  才会返回；传 `direction=income` 可查看大额收入/退款。

## 固定支出和可变支出

阶段 3 使用可解释的确定性启发式，不调用模型，也不声称这是最终财务分类：

- 在一级/二级分类、商户和描述中查找固定关键词，例如房租、房贷、水电、物业、
  宽带、手机、保险、社保、公积金、学费、订阅、会员，以及对应的英文关键词。
- 命中任一关键词的支出计入固定支出；未命中的支出计入可变支出。
- 收入、转账和被排除记录不进入固定/可变支出。退款状态的原始支出行既然仍按
  支出毛额统计，也按同一关键词规则归入固定或可变支出；退款状态的收入回款行属于
  收入，不进入固定/可变支出。
- 关键词规则后续可以版本化；当前结果应理解为估算。

## 预算和比较

- `budget_minor` 必须是非负整数。
- `used_minor` 等于周期内支出毛额。
- `remaining_minor = max(budget_minor - used_minor, 0)`。
- `over_budget_minor = max(used_minor - budget_minor, 0)`。
- 预算为零时利用率返回 `0`，但仍会正确返回超支金额。
- `mode=previous` 默认比较紧邻的同长度前一周期；`mode=yoy` 默认比较上一年
  的对应周期。也可以通过 `compare_from` 和 `compare_to` 显式指定比较周期。
- 比较结果的 `delta` 为当前值减比较值；比较值为零时 `delta_percent` 为 `null`，
  避免制造无意义的无限百分比。

## 错误和边界

- `from >= to`、负预算、负大额阈值和不支持的粒度会返回结构化错误。
- 多币种周期返回 `STATS_VALIDATION_ERROR`，不会随机选择一个币种。
- 本阶段尚未实现 `evidence_id`；统计工具在阶段 4 接入时必须复用这里的
  `Stats Service` 和同一套口径。
